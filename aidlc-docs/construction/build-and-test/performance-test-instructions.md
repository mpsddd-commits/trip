# Performance Test — trip

## 판정: **해당 없음 (N/A)**

성능 테스트를 수행하지 않았습니다. 근거는 다음과 같습니다.

| 근거 | 내용 |
|---|---|
| **SC-8** | 단독 사용자용 로컬 애플리케이션이다. 동시 사용자가 1명이다 |
| **NFR-14** | 기본 바인딩이 `127.0.0.1` 이다. 부하가 들어올 경로 자체가 없다 |
| **CON-2** | 병목은 우리 코드가 아니라 **외부 API 일일 쿼터**다. 부하를 걸면 쿼터만 태운다 |

## 대신 설계로 다룬 것

| 관심사 | 대응 | 검증 |
|---|---|---|
| 외부 호출 폭증 | TTL 캐시(NFR-4) · Directions `O(n)` 상한(BR-28) | 단위 테스트 + PBT P-21·P-22 |
| 최적화 시간 폭발 | `n<=8` 완전탐색, 그 이상 2-opt + 시간 상한(BR-22) | PBT P-09·P-10 |
| 응답 크기 | 프런트 초기 번들 **gzip 약 93KB** (목표 1MB) | `npm run build` 실측 |
| 메모리 | 컨테이너 상한 1GB / CPU 1.5 (ID-5) | `docker compose` 설정 |
| 쿼터 소진 | 레이트 리밋 3단(BR-49) + 인메모리 계측(CD-1) | 단위 테스트 |

## 나중에 필요해지는 조건

아래 중 하나라도 해당하면 이 판정을 다시 검토해야 합니다.

- `BIND_HOST=0.0.0.0` 으로 여러 사람이 함께 쓰기 시작할 때
- 실 API 키를 넣고 하루 수백 건 이상 생성할 때
- 여행 데이터가 수천 건 쌓여 SQLite 단일 파일이 커질 때

그때는 **먼저 측정할 대상**이 이것들입니다:
`POST /api/trips/{id}/generate` 의 전체 지연 · SQLite 쓰기 경합 · 캐시 적중률.
