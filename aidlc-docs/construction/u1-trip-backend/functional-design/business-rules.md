## 1. 여행 생성·검증 (BR-01 ~ BR-05)

| ID | 규칙 | 근거 |
|---|---|---|
| **BR-01** | 여행 기간은 **1일 이상 10일 이하** [설정 `MAX_TRIP_DAYS=10`]. 초과 시 `VALIDATION_ERROR` | FR-1, Q18=A |
| **BR-02** | 하루 항목 수는 **최대 15개** [설정 `MAX_ITEMS_PER_DAY=15`], 여행 전체 항목 수는 **최대 100개** [설정 `MAX_ITEMS_PER_TRIP=100`] | FR-1, Q18=A, NFR-4 |
| **BR-03** | `day_end_time > day_start_time` 이어야 한다. 기본값 `09:00` ~ `21:00` | FR-1 |
| **BR-04** | 동행 인원은 1~20명, 목적지는 1~50자, 여행 이름은 1~100자, 스타일 태그는 0~8개 | FR-1, SEC-05 |
| **BR-05** | 모든 문자열 입력은 최대 길이를 강제하고, HTML 특수문자를 이스케이프한다. 요청 본문 크기 상한 **1MB** [설정] | SEC-05 |

> **BR-02 의 실질적 의미**: 그라운딩은 항목당 지역검색 1회이므로 **항목 수 = 외부 호출 수**입니다. 이 상한이 곧 비용 상한입니다.

## 2. LLM 초안 생성 (BR-06 ~ BR-09)

| ID | 규칙 | 근거 |
|---|---|---|
| **BR-06** | 모델은 **`claude-sonnet-5`** [설정 `LLM_MODEL`], 응답은 **구조화 출력(도구 호출)로 스키마를 강제**한다 | Q3=A |
| **BR-07** | 응답 수신 후 **서버에서 한 번 더 스키마를 검증**한다. 검증 실패 시 최대 **2회 재시도** [설정 `LLM_MAX_RETRIES=2`] 후 `job=failed` + `AuditEvent(LLM_SCHEMA_REJECTED)` | SEC-13, Q3=A |
| **BR-08** | LLM 응답에서 수용하는 필드는 **`raw_name` / `category_hint` / `suggested_stay_minutes` / `reason` / `preferred_time_slot` 다섯 가지뿐**이다. 주소·좌표·전화·영업시간·가격은 **수용하지 않으며 타입에도 존재하지 않는다** | Q4=A, DD-12, CON-7 |
| **BR-09** | LLM 이 반환한 항목 수가 BR-02 상한을 넘으면 **초과분을 잘라낸다**(오류가 아님). 각 일자별로 앞에서부터 15개까지 유지 | BR-02, NFR-3 |

## 3. 장소 그라운딩 (BR-10 ~ BR-18) 🔴

| ID | 규칙 | 근거 |
|---|---|---|
| **BR-10** | 지역검색 질의는 **`"{목적지} {장소명}"`** 형태로 구성한다. `display=5`(API 상한, CON-2) | FR-3, FR-6 |
| **BR-11** | **일치 판정은 3조건 AND**: ① 정규화 유사도 **≥ 0.60** [설정 `RESOLVE_SIMILARITY_THRESHOLD`] ② 검색 결과 주소가 목적지를 포함 ③ 카테고리 힌트가 있으면 대분류 일치(힌트 없으면 통과). 셋 중 하나라도 실패하면 그 결과는 후보에서 제외 | **Q1=A**, CON-7 |
| **BR-12** | 조건을 통과한 후보가 하나도 없으면 **미해결**로 분류하고, **가장 근접했던 결과의 이름·유사도·실패 사유를 기록**해 사용자 판단을 돕는다 | FR-3 |
| **BR-13** | 그라운딩 결과에 따른 job 상태: 해결률 **100% → `succeeded`** / **1~99% → `partial`** / **0% → `failed`** | **Q2=A**, DD-23 |
| **BR-14** | 지역검색 `title` 의 HTML 강조 태그(`<b>` 등)를 **저장 전에 제거**한다. 제거 후 `<` `>` 가 남아 있으면 안 된다 | SEC-05 |
| **BR-15** | 좌표는 **위도 33.0~39.0 / 경도 124.0~132.0** 범위를 벗어나면 저장을 거부하고 `INVALID_COORDINATE` 로 미해결 처리한다 | Q2=A, 좌표계 오해석 방어 |
| **BR-16** | 지역검색 결과가 0건이면 `NO_SEARCH_RESULT`, API 호출 자체가 실패하면 `SEARCH_UNAVAILABLE` 로 미해결 처리한다. **두 경우 모두 파이프라인을 중단하지 않는다** | FR-3, NFR-3 |
| **BR-17** | 같은 여행 내에서 **좌표(소수 5자리 반올림)가 같거나 정규화 이름이 같은** 장소는 중복으로 보고, **먼저 해석된 것을 유지**하고 뒤의 것은 폐기한다 | FR-3 |
| **BR-18** | **미해결 후보는 어떤 경우에도 `ItineraryItem` 이 되지 않는다.** `UnresolvedCandidate` 로만 존재하며 사용자가 직접 검색해 담아야 일정에 들어간다 | **FR-3, CON-7** |

> **BR-18 이 환각 차단의 최종 방어선**입니다. 이 규칙을 우회하는 코드 경로가 생기면 설계 위반입니다.

| **BR-20** | 목적함수는 **총 이동시간 단독**이다. 거리·비용·시간대 적합도는 목적함수에 포함하지 않는다 | **Q5=A** |
| **BR-21** | LLM 의 `preferred_time_slot` 은 **초안 배치 순서에만** 반영되고, 사용자가 순서 최적화를 실행하면 **무시**된다. 값은 표시용으로 보존한다 | Q5=A, BR-08 |
| **BR-22** | 2-opt 탐색은 다음 중 **먼저 도달하는 조건**에서 종료한다: 개선 없는 반복 **50회** / 총 반복 **1000회** / 경과 **200ms** [설정 3종]. 종료 시점의 최선해를 반환하며 **항상 유효한 순서를 반환한다** | **Q6=A**, NFR-1 |
| **BR-23** | 항목 수 **n ≤ 8** 이면 완전탐색을 사용한다. 이 경로는 PBT 오라클(P-09)과 동일한 구현이다 | Q6=A, PBT-05 |

## 6. 타임라인·경고 (BR-31 ~ BR-35)

| ID | 규칙 | 근거 |
|---|---|---|
| **BR-31** | `time_fixed=true` 인 항목의 도착 시각은 **항상 `fixed_time` 과 일치**한다. 어떤 계산도 이 값을 변경하지 않는다 | **Q7=A**, PBT P-04 |
| **BR-32** | 앞 일정 때문에 고정 시각에 도착이 불가능하면 **`FIXED_TIME_CONFLICT` 경고를 부착**하되, 시각은 그대로 두고 앞 항목의 체류시간도 자동 축소하지 않는다 | **Q7=A** |
| **BR-33** | 항목의 종료 시각이 `day_end_time` 을 넘으면 **`DAY_OVERFLOW` 경고를 부착**하되, **다음 날로 자동 이동하거나 삭제하지 않는다** | **Q8=A** |
| **BR-34** | 모든 경고는 **표시 전용**이며 저장·조회·편집을 차단하지 않는다 | Q7=A, Q8=A |
| **BR-35** | **영업시간 경고는 `OpeningHours` 레코드가 존재할 때만** 산출한다. 레코드가 없으면 어떤 경고도 만들지 않는다. 영업시간은 **사용자 입력으로만** 채워지며 외부 API 나 LLM 에서 자동 수집하지 않는다 | **Q10=A**, FR-13 개정, CON-7 |

> **BR-35 배경**: 네이버 지역검색 API 응답에 영업시간 필드가 없습니다. LLM 추정값을 쓰면 근거 없는 사실 주장이 되어 CON-7 위반입니다.

## 10. 외부 호출·캐시·쿼터·레이트 리밋 (BR-47 ~ BR-51)

| **BR-51** | 레이트 리밋 초과·쿼터 소진·외부 인증 실패는 **보안 이벤트로 감사 로그에 기록**한다 | SEC-14 |
