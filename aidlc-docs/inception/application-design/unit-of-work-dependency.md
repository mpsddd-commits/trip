## 1. 의존성 매트릭스

행 = 의존하는 쪽, 열 = 의존되는 쪽

| | u1-trip-backend | u2-trip-web | u3-trip-android |
|---|:-:|:-:|:-:|
| **u1-trip-backend** | — | **B** | — |
| **u2-trip-web** | **C** | — | **R** |
| **u3-trip-android** | — | **U** | — |

| 기호 | 의미 | 강도 |
|---|---|---|
| **C** | Contract — 빌드 시 타입 생성으로 강제되는 API 계약 | 강 |
| **B** | Bundle — 빌드 산출물을 이미지에 포함 (u1 이 u2 의 `dist/` 를 복사) | 빌드 시에만 |
| **U** | URL — 런타임 HTTP 로드. 코드·빌드 산출물 참조 없음 (UD-5) | 약 |
| **R** | Runtime bridge — 웹이 브리지 존재를 감지해 선택적으로 사용 | 선택적 |

### 순환 검증

```
u2 --C--> u1 --B--> u2 ?
```
겉보기엔 순환이지만 **시점이 다릅니다**:
- `u2 --C--> u1` 는 **개발 시점** 의존 — 커밋된 타입 파일을 사용하므로 빌드 시 백엔드가 필요 없습니다 (UD-3)
- `u1 --B--> u2` 는 **패키징 시점** 의존 — Docker 멀티스테이지에서 web 빌드가 먼저 끝난 뒤 복사

→ 빌드 그래프상 `web-build → runtime` 단방향이며 **순환 0건** ✅

```
u3 --U--> u2 --R--> u3 ?
```
- `u3 --U--> u2` 는 런타임 URL 로드
- `u2 --R--> u3` 는 **선택적 기능 탐지**(`window.tripBridge` 존재 확인). 브리지가 없어도 u2 는 웹 폴백으로 완전히 동작합니다

→ 컴파일·빌드 의존이 양쪽 모두 없으므로 **순환 0건** ✅

## 2. 유닛 간 계약 명세

### 계약 ① u1 → u2 : REST API (OpenAPI)

| 항목 | 내용 |
|---|---|
| **원천** | `backend/app/api/` 의 Pydantic 스키마(C33) → FastAPI OpenAPI 문서 |
| **소비** | `web/src/shared/api/generated.ts` |
| **동기화 수단** | `npm run gen:api` — `openapi-typescript` 로 생성 후 **저장소에 커밋** (UD-3) |
| **불일치 검출** | `tsc` 컴파일 오류 |
| **변경 절차** | ① 백엔드 스키마 수정 → ② 백엔드 기동 후 `gen:api` 실행 → ③ 생성 파일 커밋 → ④ 프론트 타입 오류 해소 |
| **엔드포인트 목록** | `application-design/component-methods.md` §7 (19개) |

**⚠️ 규율**: 생성 파일을 손으로 수정하지 않습니다. 파일 상단에 자동 생성 경고 주석을 넣습니다.

### 계약 ② u2 ↔ u3 : 브리지 메시지 (UD-4 — 본 문서가 단일 진실 공급원)

브리지 이름: `tripBridge`
전송 방식: `WebViewCompat.addWebMessageListener` (오리진 허용목록 적용) / 구형 기기는 `@JavascriptInterface` 폴백 (DD-19)

#### 웹 → 네이티브 (요청)

| `type` | 페이로드 | 의미 |
|---|---|---|
| `openMap` | `{ appUrl: string, webUrl: string }` | 네이버지도 앱 실행 시도 후 실패 시 `webUrl` (FR-23, FR-24) |
| `share` | `{ title: string, text: string, url: string }` | 시스템 공유 시트 (FR-28) |
| `requestLocation` | `{ requestId: string }` | 위치 권한 요청 후 응답 (FR-28) |

#### 네이티브 → 웹 (응답)

| `type` | 페이로드 | 의미 |
|---|---|---|
| `locationResult` | `{ requestId: string, lat: number \| null, lng: number \| null, denied: boolean }` | `requestLocation` 응답. 거부 시 `denied: true` |
| `bridgeReady` | `{ version: string }` | 브리지 초기화 완료. 웹은 이 신호 또는 객체 존재로 네이티브 여부 판정 |

#### 계약 규율

1. **본 문서를 먼저 고치고** 양쪽 코드를 수정합니다 (UD-4)
2. 위 5종 외의 메시지를 추가하지 않습니다. 파일 접근·임의 인텐트·저장소 접근은 **금지** (SEC-11)
3. 웹은 브리지 부재를 항상 가정하고 폴백 경로를 유지합니다 (W14)
4. 네이티브는 **허용 오리진에서 온 메시지만** 처리합니다 (SEC-08)
5. 상수는 양쪽에 정의합니다 — TS: `shared/bridge/protocol.ts`, Kotlin: `BridgeProtocol.kt`

### 계약 ③ u3 → u1/u2 : 접속 주소 (CA-1 해소)

| 환경 | `BIND_HOST` (u1) | `BuildConfig.BASE_URL` (u3) |
|---|---|---|
| 로컬 브라우저만 | `127.0.0.1` (기본) | — |
| 안드로이드 **에뮬레이터** | `0.0.0.0` | `http://10.0.2.2:8200` |
| 안드로이드 **실기기** (같은 LAN) | `0.0.0.0` | `http://<개발PC LAN IP>:8200` |
| 운영 배포 | 리버스 프록시 뒤 | `https://<도메인>` |

**⚠️ `BIND_HOST=0.0.0.0` 은 같은 네트워크의 다른 기기에 서비스를 노출합니다.** 기본값을 루프백으로 두고, 전환 시 경고 로그를 남깁니다 (NFR-14, SEC-07). 운영에서는 TLS 종단이 필수입니다 (CON-5).

**단일 오리진의 부가 효과** (UD-8): 웹과 API 가 같은 오리진이므로 `BASE_URL` 하나만 관리하면 됩니다. 컨테이너를 2개로 나눴다면 API 주소와 웹 주소를 각각 관리해야 했습니다.

## 4. 공유 자원과 소유권

| 자원 | 소유 유닛 | 접근 규칙 |
|---|---|---|
| SQLite `trip/data/trip.db` | **u1** | u2·u3 는 직접 접근하지 않음. API 경유만 (UD-10) |
| 로그 `trip/logs/` | **u1** | 동일 |
| 외부 API 인증 정보 | **u1** | ⚠️ **예외 1건** — NCP 지도 SDK 클라이언트 키는 구조상 u2 에 노출됨. 도메인 화이트리스트로 방어 (CON-3, Q21=A) |
| `.env` | 공유 (루트) | u1 이 대부분 소비. u2 는 빌드 시 `VITE_` 접두 변수만, u3 는 `BASE_URL` 만 (UD-14) |
| `docker-compose.yml` | 공유 (루트) | u1 컨테이너 정의 + 볼륨. u3 빌드는 별도 `Dockerfile.build` |
| 브리지 프로토콜 정의 | **본 문서** | 코드는 양쪽 복제, 문서가 원천 (UD-4) |

### 인증 정보 노출 경계

```
+-------------------------------------------------------------+
|  백엔드 전용 (절대 클라이언트 미노출)                        |
|    - 네이버 검색 API Client ID / Secret                     |
|    - Anthropic API Key                                      |
|    - NCP Directions / Geocoding 인증 정보                   |
+-------------------------------------------------------------+
|  클라이언트 노출 (구조상 불가피 — 도메인 제한으로 방어)      |

+-------------------------------------------------------------+
```
u2 가 필요로 하는 것은 **지도 SDK 키 하나뿐**입니다. 나머지 외부 호출은 전부 u1 프록시를 경유합니다 (SEC-11).

## 6. 계약 위반 시나리오와 방어

| 시나리오 | 결과 | 방어 |
|---|---|---|
| 백엔드가 응답 필드를 제거했는데 타입을 재생성하지 않음 | 프론트 런타임 오류 | `gen:api` 를 빌드 스크립트에 포함 권고 + 생성 파일 커밋 규율 (UD-3) |
| 브리지 메시지 이름 오타 | 기능 무반응 | 양쪽 상수 파일 사용, 리터럴 직접 사용 금지 (UD-4) |
| 웹이 브리지 존재를 전제하고 폴백 누락 | 브라우저에서 기능 실패 | W14 가 유일한 분기점. 컴포넌트는 W14 만 호출 (DD-11) |
| 안드로이드가 딥링크 URL 을 자체 생성 | 웹과 규칙 불일치 | DD-11 — u3 는 URL 을 만들지 않고 받아서 실행만 함 |
| `BIND_HOST=0.0.0.0` 을 되돌리지 않고 방치 | LAN 노출 | 기동 시 경고 로그 + README 명시 (NFR-14, SEC-07) |
| u3 가 u2 빌드 산출물을 번들 | 웹 갱신마다 앱 재배포 필요 | UD-5 — 런타임 URL 의존만 허용 |
