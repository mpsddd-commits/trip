# 운영 가이드 — trip

**작성**: 2026-08-14 (Operations 스테이지)

> **AI-DLC v1.0.1 의 Operations 는 플레이스홀더입니다.** 룰셋은 이 단계가
> "향후 확장 예정"이며 워크플로가 Build and Test 로 끝난다고 명시합니다.
> 다만 룰셋이 제시한 향후 범위(배포·모니터링·장애 대응·유지보수·프로덕션 준비도)를
> **이 프로젝트에 맞게** 채워 두는 편이 실제로 쓰는 데 도움이 되므로 작성했습니다.
> 방법론이 요구해서가 아니라 앱을 굴리려면 필요해서 있는 문서입니다.

## 0. 이 시스템의 성격을 먼저 이해하세요

| 사실 | 의미 |
|---|---|
| **인증이 없습니다** (CA-3) | 여행 UUID 를 아는 사람은 누구나 조회·편집합니다 |
| **기본 바인딩이 `127.0.0.1`** (NFR-14) | 같은 PC 의 브라우저에서만 접근됩니다 |
| **단일 프로세스** (`--workers 1`) | 서킷·레이트리밋·세마포어가 전부 프로세스 내 상태입니다 |
| **SQLite 단일 파일** | 백업 = 파일 하나. 다중 인스턴스는 불가 |
| **외부 API 쿼터가 병목** (CON-2) | 부하 문제가 아니라 **비용·한도** 문제입니다 |

이 다섯 가지가 아래 모든 운영 판단의 전제입니다.

## 1. 일상 운영

### 기동 / 정지

```bash
docker compose up -d        # 기동 (약 30초 후 healthy)
docker compose ps           # 상태 확인
docker compose down         # 정지 (데이터 유지)
```

### 상태 점검 3가지

```bash
curl -s http://127.0.0.1:8200/api/health          # 살아 있는가
curl -s http://127.0.0.1:8200/api/health/ready    # 무엇이 데모 모드인가 / 쿼터
docker compose logs --tail 50 app                 # 최근 로그
```

`/api/health/ready` 의 `modes` 가 전부 `real` 이 아니면 그 기능은 **데모 데이터**로 동작합니다.
화면에도 닫을 수 없는 배너가 뜹니다 (WBR-30). 오류가 아니라 설계된 동작입니다 (FR-33).

### 로그

`logs/app.jsonl` — 한 줄 JSON, 일 단위 로테이션, **90일 보존** (SEC-14).

```bash
docker compose logs app | grep '"level": "ERROR"'
grep '"correlation_id": "096de172..."' logs/app.jsonl   # 오류 응답 본문의 ID 로 추적
```

> 🔴 **로그 마스킹을 믿되, 확인은 하세요.** API 키·토큰은 마스킹됩니다.
> 다만 Build and Test 에서 `Authorization: Bearer <토큰>` 의 **토큰이 그대로 남는** 구멍이
> 발견돼 고쳤습니다. 새 외부 API 를 붙일 때는 그 API 의 인증 헤더 형태가
> `logging_config.py` 의 패턴에 걸리는지 **직접 확인**하세요.

## 2. 백업과 복구

```bash
./scripts/backup-db.sh        # Windows: .\scripts\backup-db.ps1
# → data/backup-YYYYMMDD-HHMMSS.db
```

> 🔴 **`data/` 폴더를 그냥 복사하는 것은 백업이 아닙니다.**
> WAL 모드라 최근 트랜잭션이 `trip.db` 본체가 아니라 `trip.db-wal` 에 있습니다.
> 스크립트는 SQLite 온라인 백업 API 로 일관된 스냅숏을 만듭니다.

권장 주기: **여행 일정을 새로 만든 날**. 데이터가 자주 바뀌지 않는 앱이라
정기 스케줄보다 작업 후 백업이 실질적입니다.

### 복구

```bash
docker compose down
cp data/backup-20260814-120000.db data/trip.db
rm -f data/trip.db-wal data/trip.db-shm     # 옛 WAL 이 남아 있으면 안 됩니다
docker compose up -d
```

### 🔴 백업으로 지킬 수 없는 것

**브라우저의 여행 목록은 서버에 없습니다.** 여행 데이터는 서버 DB 에 있지만,
"내가 만든 여행이 무엇인지"(UUID 목록)는 브라우저 localStorage 에만 있습니다 (DD-21).

브라우저 데이터를 지우면 **여행은 살아 있는데 찾아갈 수 없게 됩니다.**
그래서 화면에 상시 고지와 **목록 내보내기/가져오기**를 두었습니다 (WBR-06~08).
사용자에게 이 기능을 안내하세요. 서버 백업만으로는 막지 못합니다.

## 3. 실 API 로 전환하기

1. 키 발급 — [네이버 개발자센터](https://developers.naver.com) · [NCP](https://www.ncloud.com) · [Anthropic Console](https://console.anthropic.com)
2. `cp .env.example .env` 후 값 입력
3. 🔴 **NCP 콘솔에서 지도 키의 Web 서비스 URL(도메인 화이트리스트) 등록**
4. `docker compose up -d`
5. `/api/health/ready` 에서 해당 항목이 `real` 인지 확인

### 지도 키만 다르게 취급합니다

`NCP_MAP_CLIENT_KEY` 는 **구조상 브라우저에 노출됩니다** (CON-3). SDK 가 클라이언트에서
동작하므로 숨길 방법이 없습니다. 방어 수단은 **도메인 화이트리스트 하나뿐**입니다.
등록하지 않으면 누구나 그 키로 자기 사이트에서 지도를 쓰고, 비용은 당신이 냅니다.

나머지 키(검색·경로·LLM)는 백엔드에서만 쓰이며 클라이언트로 나가지 않습니다.
`GET /api/config` 응답에 키가 섞이지 않는지 자동 테스트가 지키고 있습니다.

### 부분 전환도 괜찮습니다

키를 하나만 넣어도 됩니다. 나머지는 계속 데모 모드로 돌고 화면이 그 사실을 알립니다.
지도만 실물로 보고 싶으면 `NCP_MAP_CLIENT_KEY` 만 넣으세요.

## 4. 비용 통제

인증 정보를 넣는 순간 외부 호출이 **실제 비용**이 됩니다. 기본 상한:

| 항목 | 기본값 | 설정 키 |
|---|---|---|
| AI 생성 (IP당) | 5회/시간 | `RATE_EXPENSIVE_PER_HOUR` |
| **AI 생성 (전역)** | **50회/일** | `RATE_EXPENSIVE_GLOBAL_PER_DAY` |
| 검색·경로 (IP당) | 60회/분 | `RATE_EXTERNAL_PER_MIN` |
| 지역검색 쿼터 | 25,000회/일 | `QUOTA_NAVER_LOCAL_PER_DAY` |

전역 일일 상한은 **DB 에 기록되어 재시작으로 초기화되지 않습니다.**
컨테이너를 껐다 켜서 한도를 우회할 수 없습니다.

외부 응답은 캐시됩니다 — 지역검색 7일, 경로 1일. 항목 **순서만** 바꾸는 편집은
외부 호출을 전혀 일으키지 않습니다 (BR-29). 경로 호출은 항목 수에 비례(`O(n)`)합니다.

### 비용이 예상보다 많이 나오면

```bash
curl -s http://127.0.0.1:8200/api/health/ready    # quota 확인
grep '"quota' logs/app.jsonl | tail -50
```

먼저 볼 것은 **캐시가 동작하는지**입니다. 같은 검색어가 반복 호출되고 있다면
캐시 키 정규화나 TTL 을 의심하세요. Build and Test 에서 **캐시를 읽을 때마다 예외가 나서
캐시가 통째로 무력화된** 결함이 있었습니다. 같은 증상이면 로그에 `TypeError` 가 보입니다.

## 5. 유지보수

### 의존성 점검 (권장 월 1회)

```bash
./scripts/audit-deps.sh       # Windows: .\scripts\audit-deps.ps1
```

세 가지를 봅니다:
1. Python 런타임·개발 의존성 (`pip-audit`)
2. Node 런타임 의존성 (`npm audit`)
3. **베이스 이미지 다이제스트 드리프트** — 고정한 `@sha256:` 이 상위 태그와 달라졌는지

3번이 "상위 이미지가 갱신됐습니다" 라고 하면 보안 패치가 나왔을 가능성이 큽니다.
변경 내역을 확인하고 `Dockerfile` 의 다이제스트를 교체한 뒤 재빌드·재테스트하세요.

> 다이제스트 고정은 **재현성**을 위한 것이지 "영원히 안 바꾸겠다"는 뜻이 아닙니다.
> 고정하지 않으면 같은 태그가 조용히 다른 내용으로 바뀌고, 고정만 하고 갱신하지 않으면
> 알려진 취약점을 안고 갑니다. 둘 다 문제라서 정기 점검이 필요합니다.

### 업그레이드 절차

```bash
# 1. 백업
./scripts/backup-db.sh

# 2. 되돌릴 지점을 남긴다
docker tag trip-app:latest trip-app:backup

# 3. 의존성 수정 후 테스트 (컨테이너에서)
docker run --rm -v "c:/경로/trip/backend:/app" -w /app python:3.12-slim \
  sh -c "pip install -q -r requirements-dev.txt && python -m pytest"

# 4. 재빌드 · 재기동 · 확인
docker compose build && docker compose up -d
curl -s http://127.0.0.1:8200/api/health/ready
```

**롤백**
```bash
docker compose down
docker tag trip-app:backup trip-app:latest
docker compose up -d
```
> 스키마 마이그레이션이 적용된 뒤라면 DB 도 백업본으로 함께 되돌려야 합니다.

### SBOM 갱신

```bash
python scripts/generate-sbom.py aidlc-docs/construction/build-and-test/sbom/sbom.json
```

## 6. 장애 대응

증상 → 원인 → 조치. **위에서부터** 확인하세요.

| 증상 | 가장 흔한 원인 | 확인 | 조치 |
|---|---|---|---|
| `docker compose up` 즉시 실패 | `env_file` 설정 | 메시지에 `.env not found` | `docker-compose.yml` 의 `required: false` 확인 |
| 브라우저가 빈 화면 | 컨테이너 미기동 | `docker compose ps` | `up -d` 후 30초 대기 |
| **전 API 가 500** | 로그 필터·캐시 예외 | 로그에 `TypeError` | 아래 §6.1 |
| 지도가 안 뜸 | 키 없음 / 도메인 미등록 | `/api/config` 의 `map_client_key` | 키 설정 + NCP 화이트리스트 |
| 검색 결과가 이상함 | 데모 모드 | `ready` 의 `modes` | 네이버 키 설정 |
| AI 생성이 안 됨 | 키 없음 또는 일일 한도 | `ready` 의 `quota` | 한도면 다음 날까지 대기 |
| 생성이 `partial` 로 끝남 | 일부 장소 미해결 | 화면의 "확인 필요" 패널 | **정상 동작**. 직접 검색해 채우세요 (BR-18) |
| 일정은 있는데 목록에서 사라짐 | 브라우저 데이터 삭제 | — | 공유 링크 / 목록 가져오기 (§2) |
| 안드로이드 앱이 빈 화면 | 평문 HTTP 차단 또는 주소 오설정 | 앱 오류 화면에 주소가 표시됨 | §7 |

### 6.1 전 API 가 500 일 때

`logs/app.jsonl` 에서 `TypeError` 를 찾으세요. 과거에 두 번 있었습니다.

1. **로그 필터가 예외를 던짐** — `logging.Filter` 는 `Handler.emit()` 의 try/except **밖**에서
   실행됩니다. 필터에서 난 예외가 **로그를 호출한 코드까지 튀어나갑니다.**
   라이브러리가 `%d` 로 남기는 로그 한 줄이 요청 전체를 죽일 수 있습니다.
2. **캐시 만료 비교** — SQLite 에서 읽은 naive datetime 과 aware `utcnow()` 비교.

둘 다 고쳤고 회귀 테스트가 있습니다. 비슷한 코드를 새로 넣을 때 같은 함정을 조심하세요.

## 7. 안드로이드 운영

```bash
./scripts/build-android.sh                            # 에뮬레이터
./scripts/build-android.sh http://192.168.0.10:8200   # 실기기
```

실기기로 붙이려면 서버도 열어야 합니다 (`.env` 에 `BIND_HOST=0.0.0.0` 후 재기동).

> 🔴 **`BIND_HOST=0.0.0.0` 은 같은 네트워크의 누구나 접근할 수 있다는 뜻입니다.**
> 인증이 없습니다. 공용 Wi-Fi 에서 쓰지 마세요. 끝나면 `127.0.0.1` 로 되돌리세요.
> 기동 로그에 경고가 나오는 것은 정상입니다.

### 🔴 APK 를 새로 배포할 때마다

`android/README.md` 의 **실기기 확인 체크리스트 8항목**을 실행하세요.

u3 의 대표적 실패(평문 차단 · 다운로드 무시 · `window.open` 무시 · 위치 미회신)는
**전부 컴파일을 통과하고 예외도 내지 않습니다.** 빌드 성공은 동작 보증이 아닙니다.
증상이 "오류"가 아니라 **"아무 일도 일어나지 않음"** 이라 로그로도 안 잡힙니다.

## 8. 프로덕션 준비도 체크리스트

현재 구성은 **로컬 사용 전용**입니다. 인터넷에 노출하려면 아래가 **모두** 선행돼야 합니다.
하나라도 빠지면 공개하지 마세요.

- [ ] **리버스 프록시 + TLS** — 현재 HTTPS 가 없습니다
- [ ] **인증 도입** — 지금은 UUID 만 알면 누구나 접근합니다
- [ ] **시크릿 관리** — `.env` 파일 대신 시크릿 매니저
- [ ] **상태 외부화** — 🔴 서킷·레이트리밋·작업 세마포어가 **프로세스 내 상태**입니다.
      워커를 늘리면 이 통제들이 **오류 없이 조용히 무력화**됩니다. Redis + PostgreSQL 선행 필요
- [ ] **레이트 리밋 재검토** — 현재 값은 1인 사용 기준입니다
- [ ] **지도 키 도메인 화이트리스트** 등록
- [ ] **백업 자동화** — 현재는 수동 스크립트뿐입니다

> 4번을 특히 조심하세요. `--workers 2` 로 바꾸는 것만으로 비용 통제가 무너지는데
> **아무 오류도 나지 않습니다.** `Dockerfile` 의 `--workers 1` 옆에 이유를 적어 두었습니다.

## 9. 모니터링 — 무엇을 볼 것인가

이 규모에 별도 모니터링 스택은 과합니다. 대신 세 가지를 주기적으로 보세요.

| 대상 | 방법 | 무엇을 찾는가 |
|---|---|---|
| **쿼터** | `/api/health/ready` 의 `quota` | 예상보다 빠른 소진 = 캐시 미동작 의심 |
| **서킷** | 같은 응답의 `circuits` | `open` 이 지속 = 외부 API 장애 또는 키 만료 |
| **오류율** | `grep '"level": "ERROR"' logs/app.jsonl \| wc -l` | 급증 = §6.1 |

컨테이너 헬스체크는 **liveness 경로만** 씁니다 (ND-14). 외부 API 를 부르지 않으므로
헬스체크가 일일 쿼터를 소모하지 않습니다.

## 10. 알려진 제약 (설계상 그런 것들)

버그가 아니라 결정입니다. 고치려 하기 전에 근거를 보세요.

| 제약 | 근거 |
|---|---|
| 대중교통 소요시간이 추정치 | 네이버가 대중교통 경로 API 를 제공하지 않습니다 (CON-1). 화면에 "추정" 배지를 붙이고 실제 길찾기는 네이버지도 앱에 넘깁니다 |
| 영업시간을 직접 입력해야 함 | 지역검색 응답에 영업시간 필드가 없습니다 (FR-13 축소) |
| AI 가 만든 장소를 그대로 안 씀 | 실제 검색으로 3조건 검증을 통과해야 일정에 들어갑니다 (BR-11·BR-18). 통과 못 하면 "확인 필요" 로 남습니다 |
| 여행 목록이 브라우저에만 있음 | 인증이 없으므로 서버가 "누구의 여행"인지 알 수 없습니다 (DD-21) |
| 단일 워커 | §8 4번 |
